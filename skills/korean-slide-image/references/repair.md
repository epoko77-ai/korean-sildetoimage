# 부분 편집과 픽셀 보존

생성형 편집은 이미지 도구로, 허용된 crop·합성·검증은 이 스크립트로 처리한다. 스크립트는 Pillow가 필요하며 별도 API를 호출하지 않는다. 생성 결과·원본·마스크를 모두 무손실 PNG로 다룬다. 기존 출력이 있으면 덮어쓰지 않고 실패한다.

## 기준 이미지 정규화

```bash
python3 "$SKILL_DIR/scripts/patch_image.py" prepare \
  --image source.png --out "$RUN_DIR/base.png"
```

EXIF 방향을 적용하고 RGBA로 한 번 변환한다. ICC 프로파일은 보존한다. 이후 보존 비교의 기준은 이 파일이다. JPEG 재압축이나 최종 이미지 전체 리사이즈는 이 단계 이후에 하지 않는다. 사용자용 축소본이 필요하면 검증된 원본 PNG와 별도로 내보내고 픽셀 동일성 주장은 원본 PNG에 한정한다.

## 두 영역을 정하고 추출

```bash
python3 "$SKILL_DIR/scripts/patch_image.py" crop \
  --base "$RUN_DIR/base.png" \
  --context 120 140 920 540 --edit 240 260 780 360 \
  --out "$RUN_DIR/edit-01-input.png" --job "$RUN_DIR/edit-01-job.json"
```

모든 좌표는 원본 기준 `[left, top, right, bottom]`. context는 편집 도구가 참고할 영역이고 edit는 실제 바꿀 수 있는 영역이다. edit가 context 안에 들어와야 한다. 글자의 그림자·받침을 자르지 않는다. 배경이 단순한 곳에 edit 경계를 놓고 필요하면 한 줄 전체를 잡는다.

작은 글자를 확대해 편집할 필요가 있을 때만 `--scale 2`를 사용한다. context만 확대하며, 후보와 합성 단계는 동일 배율을 사용한다. 확대가 원본에 없던 정보를 복원한다고 설명하지 않는다. 기본은 1이다. 도구가 작은 crop과 다른 크기를 자꾸 반환하면 **전체 이미지를 context로 주고 edit만 작게 지정**할 수 있다. 이 경우에도 출력 크기·배치가 맞는지 검사한다.

job 파일에는 기준본·crop 파일의 SHA-256, 원본 크기, 두 영역, 배율이 담긴다. 중간에 기준본이 바뀌면 합성을 거절한다. 서로 떨어진 오류는 별도 작업으로 처리한다. 영역이 겹치면 새로 승인한 기준본에서 다음 crop을 만든다.

도구 호출 전에 이 job을 `workflow.py freeze --preserve-job`으로 연결한다. 실제 문구·참조 파일과 함께 고정하는 명령은 [workflow.md](workflow.md)를 따른다.

## 생성형 교정

crop 이미지를 실제로 본 다음 이미지 편집 도구에 전달한다. 전체 이미지가 스타일 참고라면 역할을 구분한다. 좌표를 글로 설명하는 것은 마스크 강제가 아니다.

```text
입력 1은 편집할 원본 crop이다. <있는 경우: 입력 2는 전체 디자인 참고다.>
<정확한 위치>의 “추친 계획”을 “추진 계획”으로 바꾼다.
정답 문구: “추진 계획”. 추가 문구를 넣지 않는다.
기존 글자의 서체 느낌·굵기·크기·자간·기준선·색·질감·그림자를 맞춘다.
주변의 올바른 문구와 배경·도형·테두리·조명·구도를 유지한다.
입력 crop의 화면 범위와 픽셀 크기를 유지한다.
```

한 번의 후보는 하나의 명확한 수정에 집중한다. 받침이 틀린 한글을 초성·중성·종성으로 분해하여 화면에 쓰라고 지시하지 않는다. 원문 전체를 확정 문자열로 제시한다. ‘한 글자도 틀리지 마’와 같은 강조만 반복하지 않는다.

도구 결과에 로컬 파일이 없으면 실제 제공된 산출물 경로나 다운로드 수단으로 가져온다. 없는 저장 경로·이미지 파일을 만들었다고 주장하지 않는다. 후보 크기가 다르면 명령은 실패한다. 동일 프레임의 균일 배율 차이라고 확인된 경우에만 후보를 별도 파일로 정합할 수 있다. 자동 늘이기·비율 왜곡·전체 이미지 재생성으로 해결하지 않는다.

## 영역만 합성

후보 문구와 스타일을 확인한 다음 실행한다.

```bash
python3 "$SKILL_DIR/scripts/patch_image.py" compose \
  --job "$RUN_DIR/edit-01-job.json" --candidate "$RUN_DIR/edit-01-candidate.png" \
  --out "$RUN_DIR/accepted-01.png" --report "$RUN_DIR/edit-01-check.json"
```

필요한 경우만 `--feather 2`처럼 안쪽 가장자리를 섞는다. feather는 edit 경계 **안쪽에서만** 작동하며 원래 글자나 그림자가 경계 근처에 남아 있으면 사용하지 않는다. 큰 feather로 글자의 두 겹·잔상·배경색 차이를 숨기지 않는다. 기본은 0이다.

합성은 AI가 고친 이미지 부분을 사용하는 방식이다. 일반 폰트로 텍스트를 자동 덮지 않는다. candidate의 context 바깥과 edit 바깥은 사용하지 않는다. 외부 영역의 픽셀 동일성은 검증할 수 있지만 내부의 자간·경계·질감 품질은 별도 눈검사가 필요하다.

보고서의 `candidate_guard_mean_abs_diff`는 edit 주변 4픽셀 띠의 후보와 원본 차이이며, 위치·배경 변화의 단서다. 자동 합격 점수가 아니다. 0이어도 내부 문구는 틀릴 수 있고 값이 커도 버릴 영역만 변했을 수 있다. 후보와 합성본을 함께 확대해 경계·그림자·글자 두께를 확인한다.

## 누적 보존 검사

```bash
python3 "$SKILL_DIR/scripts/patch_image.py" verify \
  --base "$RUN_DIR/base.png" --final "$RUN_DIR/accepted-02.png" \
  --reports "$RUN_DIR/edit-01-check.json" "$RUN_DIR/edit-02-check.json" \
  --out "$RUN_DIR/pixel-check.json"
```

최초 기준본에서 최종본까지 보고서의 해시 연결을 확인한다. 각 승인 영역의 합집합 밖에 변경된 RGBA 픽셀이 1개라도 있으면 종료 코드 2로 실패한다. 크기 불일치·잘못된 보고서·해시 연결 불일치는 종료 코드 1이다. 영역을 임의로 늘려 실패를 통과시키지 않는다. 원본 대비 변경 영역을 실제 허용 범위로 유지한다.

최종 PNG를 다시 열어 전체 문구와 수정 영역을 검수한다. 검수 전 후보를 `verified`로 표시하지 않는다. 재시도 한도에 도달하면 기준본·최선의 후보·남은 오타를 보관한다.

## 허용된 폰트 재렌더링

생성형 수정이 반복 실패하거나 사용자가 정확한 글자 렌더링을 선택한 경우에 적용한다. 이미 허용한 범위라면 다시 묻지 않는다. 선택되지 않은 기본 폰트로 스타일을 자동 교체하지 않는다.

1. 실제 사용할 로컬 폰트의 한글·숫자·기호 지원을 확인한다. 대체 글꼴이나 빈 사각형이 생긴 결과는 거절한다. 폰트 파일을 허락 없이 배포 패키지에 넣지 않는다.
2. 수정 단어 또는 한 줄의 크기·굵기·기준선·자간·색을 주변과 비교한다. 원문 문자열은 확정 목록에서 가져온다.
3. 기존 오자와 효과가 남지 않도록 배경을 복구한다. 단색·평탄한 영역인지 실제로 확인한다. 사진·재질·그림자 위의 복잡한 배경을 임의 단색 박스나 흐림으로 덮지 않는다. 깨끗한 배경을 확보할 수 없으면 그 문제를 먼저 해결한다.
4. 렌더링 계획을 `--kind local-font`로 고정하고 같은 job의 허용 영역 안에서 합성한다. 결과를 확대·축소해 보고 전체 문구와 영역 밖 픽셀을 다시 검사한다.

코드로 글자를 그리는 방식은 생성 모델이 철자를 그릴 때의 불확실성을 줄일 수 있다. 배경 복구와 스타일 일치까지 자동으로 해결하지는 않는다. 정확도와 디자인을 각각 판정한다.

## 도구 제한의 근거

- [OpenAI 이미지 생성 안내](https://learn.chatgpt.com/docs/image-generation): 정확한 짧은 문구 지정, 작은 단위의 반복 수정, 촘촘한 문구의 최종 검수.
- [OpenAI 마스크 편집](https://developers.openai.com/api/docs/guides/image-generation#edit-an-image-using-a-mask): 마스크는 편집 유도이며 정확한 경계 준수를 보장하지 않는다.

모델명·요금·지원 인자는 여기에 고정하지 않는다. 실행 시 실제 도구와 최신 공식 문서를 따른다.
